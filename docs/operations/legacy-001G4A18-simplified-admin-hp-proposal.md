## Smallest coherent architecture

**Admin owns configuration; one engine HP/accounting boundary owns runtime state; database operations enforce that split.** Keep [existing diagrams](../architecture/README.md): ownership does not change, only candidate API/storage complexity. No new authoring framework.

Recommend **one narrow authenticated Admin mutation RPC with an allowlisted action** (save/create/move/delete), implemented with existing role checks and small internal branches, plus the existing separate reward RPC. This is a proposed interface, not a new SQL artifact. No arbitrary table/field mutation, action-supplied authorization or broad service bypass. Save accepts dirty configuration fields only. Metadata-only save takes the creature row lock and compares touched authored fields; it neither acquires world/node/encounter gates nor changes HP, accounting or claims. Existing source locks are not retrofitted via a late-locking trigger.

Protected config/move/create/delete branches reuse the established early sorted node → party lifecycle where needed → sorted encounters → dependent rows protocol, discover/revalidate coverage and refuse/retry changes without late node locks. They retain generation/version/claim fencing, blockers and reference checks. Shared HP helpers apply max/rate changes; server derives level/rarity stats/AC with parity to [current formula](../../src/shared/formulas/creatures.ts) and [boss validator](../../src/components/admin/boss-cast-form.ts). No client full-object hp/stats/lifecycle authority. Metadata uses flat old values for touched fields; derived-stat changes compare their necessary level/rarity/max dependencies, not a nested general expected-state envelope or global tick revision.

All HP transitions reuse G4A6–G4A15 accounting/coverage code: creatures.hp durable, matching node_creature.hp synchronized; stale claims rejected, including retained same-generation reactivation. Preserve durable wounds, default5%/minute configurable0–100% with two decimals,60-second uninterrupted eligible delay, effects/actions blockers, elapsed eligible sleep accounting, no retroactive initialization, fractional rules, rate-old-time settlement, missing-HP-preserving maxima/living floor1, dead ordinary respawn and generation semantics. No new regeneration formula or heartbeat. Legacy regen/wake callers must stop independently healing when this authority activates; a NOT EXISTS(active encounter) filter or dual-row UPDATE alone is insufficient.

## Replay amendment — approval required before conflicting implementation

G4A17 consequential durable replay remains the canonical rule **until explicitly amended**. A–D otherwise remain: touched-field conflicts, retained-reference deletion refusal, limited quiet/unprojected/unreferenced unassignment and separate reward transactions. Proposed narrower policy:

| Operation | Proposed safeguard | Guarantee deliberately lost |
|---|---|---|
| Absolute metadata/config/rate/max/node assignment | Desired-value no-op first under locks, then flat touched/dependency old-value comparison. Only an actual change settles/fences; retry already at desired must not discard fractions or restart cursors. Refresh after uncertainty; if desired state was changed again, refuse/review rather than automatically reapply stale intent. | No historical result replay, global UUID binding or exactly-once audit. Identical desired current state proves convergence, not original execution. ABA changes cannot be attributed to the original request without history. |
| Create | Allocate one immutable creature UUID before dispatch; retain it through uncertain response. On duplicate identity read authorized current state and reconcile; never overwrite it or mint a fresh identity automatically. If missing after uncertain create/delete history, require manual review, not automatic recreation. | No durable create receipt, proof of historical payload or safe automatic retry after a later deletion. Browser storage loss requires reconciliation before another create. |
| Delete | Explicit confirmation, current expected identity and reference check; missing target reports already_absent, never original-success proof. Refuse retained references, no purge/cascade. Never recreate deleted IDs. | No actor/request-specific historical deletion result or receipt-backed consumed-ID registry. Existing unknown privileged callers remain outside this guarantee. |
| Rewards/non-idempotent awards | Keep existing admin_set_creature_rewards request identity/ledger/contract; preserve all existing reward, progression and inventory replay protections. Any genuinely additive future Admin operation needs its own justified replay boundary. | No weakening authorized; do not migrate their receipts into a new universal store. |

Recommend dropping seven consequential endpoints, new creature_admin_request table/cleanup/retention policy and durable replay for routine configuration **only if this amendment is approved**. Absolute config still needs atomic locking, stale-field checks and no-op detection; rate settlement is not inherently idempotent without those checks. No automatic indefinite retry after ambiguous results. Routine diagnostics/errors are enough; no new generalized audit system. If owner declines, keep G4A17 replay and revisit only that dependency—do not silently implement this alternative. This task does not approve retention or discard prior requirements.
