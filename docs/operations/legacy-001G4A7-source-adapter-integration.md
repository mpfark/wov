## New candidate integration findings and boundaries

- New entry uses a success savepoint: a JSON refusal rolls back pre-settlement and entry writes. Actual hostile source's own subtransaction also rolls back entry/accounting on doubled intent refusal. Replays bypass new settlement. These are executed SQL rollback paths, not immutable-model simulations.
- **Live-lease edge corrected locally:** passive settlement defers a live claim, but newly accepted authoritative entry must not defer old quiet credit and then erase the interval when entering combat. The wrapper fences the lease before pre-settlement, inside its rollback boundary; source entry performs its normal final version invalidation. New admission double does likewise before pre-settlement. A regression claims at70seconds (fraction5/6HP), enters at72 within the live lease, receives earned wholeHP and rejects the old proposal. No production claim behavior was changed.
- Claim is synchronized before its source lease/snapshot. Successful source-fragment commit reconciles final table blockers only for a **new** commit, never replay/refusal. No regeneration inside the pure resolver, whose catalogs and complete snapshots are absent.
- The real source generation mirror predicate preserves a new life against an old-generation row. One controlled-metadata test isolates that predicate; it is not evidence an old worker can obtain a valid new lease. The candidate wrapper separately rejects a new proposal addressing an old generation before applying fragments. Ordinary due respawn and zero-rate independence are native-tested.
- DoT fixture admission is explicit under the local authority, not a real resolver pulse. Source effect deletion/pending-action mutation and final status update execute; eligibility stays closed until final blockers resolve. A repeat unblocked observation does not restart the delay. Just-before/exact60second boundaries and fractional/re-entry behavior are tested.
- Rate edit settles old eligible time/wholeHP then clears fraction/cursor. Max edit preserves missingHP with the approved living floor1; dead max edit stays dead and later ordinary respawn uses the new max. No real loot/progression trigger stack is present.
- Quiescent reassignment still uses the G4A6 local protocol; there is no existing production transfer function to load. Full historical event/FK transfer composition, missing destination encounters/unassignment and real Admin table-write fences remain unimplemented.
