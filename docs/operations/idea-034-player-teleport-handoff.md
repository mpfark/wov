## Owner-approved reusable temporary waymarks — local implementation

Owner2026-10-23 approved one personal mark per character, created/replaced only by qualifying level22+ personal teleport from a non-teleport node. Return is reusable, never consumes/replaces/relocates the mark, and retains CP/combat/movement/party/arrival restrictions. City and Summon rules are unchanged. This supersedes the prior unresolved creation/consumption/lifetime decision; it is not installed evidence.

- Reuse character_waymark, adding only auth_session_id and last_activity_at. Existing unbound rows are immediately ineligible; no retroactive credit/session assignment. No new travel table, auth trigger, FK into Auth, cron job or global auth setting. Expired/revoked rows can remain physically stored (one per character) but are never eligible and may be replaced by a later qualifying teleport.
- waymark_live_session() is an owner-only postgres/DEFINER helper: validate the trusted JWT session claim against auth.sessions(id,user_id), with KEY SHARE. No token/session identifier is returned to the browser, logged, or placed in browser storage. character_waymark_state(uuid,boolean) is authenticated-only, rechecks own living/active character, locks character NO KEY UPDATE then mark, returns only current valid node/expiry and optionally records server-received activity. Known platform defaults are revoked object-by-object on new functions; other unexpected grants stop installation. Existing RPC owner/settings/ACL and existing table RLS/grants remain unchanged.
- The server cutoff is last_activity_at <= clock_timestamp() - interval '20 minutes'. Check after lock waits. Touching/replaying an expired mark cannot revive it. Successful new travel touches only an eligible current-session mark, inside the movement transaction; failures roll back mark/CP/position/receipt changes. Historical receipt replay performs no travel/activity writes and cannot restore a revoked/expired mark.
- The visible-input hook sends at most one touch per5 seconds while a valid mark is displayed; mount/refocus are status-only, with no polling. Idle visible-tab heartbeat is **not** activity. The threshold uses server-received input, so throttling can conservatively expire up to5 seconds before the final local input (network/suspended-tab delivery is not guaranteed). Client expiry timers are presentation only; delayed/background displays never override SQL. Existing30-minute inactivity logout, last_online heartbeat, unique-item cleanup and world sleep/wake remain unchanged.
- [Existing useAuth logout](../../src/hooks/useAuth.ts), [Admin logout](../../src/components/admin/AdminLayout.tsx), error-boundary logout and [GameContext inactivity logout](../../src/contexts/GameContext.tsx) all use Supabase Auth signOut. Its default global scope is preserved. [Supabase session documentation](https://supabase.com/docs/guides/auth/sessions) explicitly documents that completed sign-out removes affected session rows and recommends membership checks to reject still-unexpired JWTs. [Sign-out scopes](https://supabase.com/docs/guides/auth/signout) distinguish global/local/others. Binding marks to the creating session prevents a new login inheriting one. Global sign-out invalidates affected sessions; another still-live device cannot borrow the creating session's mark. No lifecycle function is executed on logout, avoiding a new node/character lock inversion.
- **Limit:** browser storage clearing, offline logout or failed Auth revocation cannot be detected as immediate server logout. Smallest safe operational solution: require existing Auth signOut to complete, surface/retry its error; until confirmed, the20-minute server activity cutoff applies. No frontend-only promise of remote revocation. Verify installed Supabase Auth contract/read visibility separately; local tests simulate session-row removal, not GoTrue/network/logout integration. Time-boxed Auth session expiration is not asserted to delete rows immediately.

Native additions cover repeated return/identity preservation, one-row replacement, city nonreplacement,20-minute cutoff/touch, expired replay, missing/malformed/foreign/new-login sessions, legacy unbound marks, Auth-delete-first and travel-first observed blocking, and exact concurrent return replay. Existing11 tests remain. Auth schema/JWT and revocation deletion are explicit dependency doubles; complete travel/arrival/0024 coverage/lifecycle source still executes. Tests do not prove hosted Auth, scheduler or independent-session gameplay behavior.
