## Canonical damage, death, persistence and rewards

```text
owned hostile intent / movement arrival
 → node-locked entry + seed current living creature generation
 → claim snapshots node_creature HP + authored creature configuration
 → pure resolver: attacks / periodic damage / reactive damage → one death proposal
 → composed commit: lease/tick/version/reference fences
   → node_creature HP/death + generation-fenced creatures mirror
   → durable participation / first reward claim / death loot / events in same transaction
```

Resolver state is keyed by technical creature_id, with generation/runtime-row checks enforced by commit. A dead row is not revived by damage commit (`is_alive = proposed AND existing`); matching-generation conditions stop a stale death mirror from overwriting a newly respawned authored generation. New-generation seeding does not revive old runtime rows; ON CONFLICT preserves the existing same-generation row and its wounds. node_creature UNIQUE(creature_id,spawn_seq) is global across encounters; an authored node reassignment does not itself relocate that existing row.

Death recipient eligibility uses durable interaction qualification for the exact spawn, not mere shared node or party membership. A qualified source may have left; an unqualified bystander is not automatically paid. Arena suppression, first-claim insertion, canonical XP adapter/additive gold and durable loot boundaries reuse B/E evidence. Current source core only applies progression/gold after newly inserted node_reward_claim; replay/conflict keys limit duplicate grants within that boundary. Do not infer full current hosted reward behavior, salvage composition or a contract-specific payout from that source chain.

**G2/E13 cross-reference:** no current canonical Assassin completion producer was located in the bounded inspected chain; the historical Combat1 producer/helper does not establish current completion. Contracts use creature UUID references, not display-name matching. G2 is accepted investigation-complete with explicit limitations; E13 remains OPEN, including non-atomic re-roll/provenance/reward questions. G4 does not fix or close it.

## HP between players, encounter end, no players and world sleep

**Partial persistence exists in source:** canonical commit mirrors wounded/dead HP to a shared authored creature row, and an existing node_creature row retains wounds when another player joins. New projection seeds current authored HP with `GREATEST(1,COALESCE(NULLIF(cr.hp,0),cr.max_hp))`, so a malformed alive zero-HP row seeds at least1/full fallback rather than preserving zero literally. This is not proof of a consistent, fully implemented shared-world HP policy across every writer, reconnect, wake and respawn.

**Two HP surfaces can diverge:** e.g. both rows have20/100HP, no old-table combat/effects row exists, and wake healing sets creatures.hp=100 while the active Combat2 node_creature remains20. Roster reads100; the next claim still reads20, and a later dirty combat proposal can mirror its outcome back. This is a source-implied composition example, not an executed fixture or hosted observation. Ordinary legacy regen similarly targets only the authored row. Row locking of individual updates does not make that pair a synchronized authority or invalidate an already claimed proposal.

**Regeneration:** the current resolver has no general positive creature-HP regeneration loop; its passive CP/regen healing branches are character behavior. Ordinary legacy regen is supported by retained SQL/scheduler source, delayed by last_damaged_at5minutes and old combat/effect guards. Canonical DoT damage updates last_damaged_at through commit, which may delay that helper, but there is no explicit node_effect/Combat2 DoT suppression predicate. Wake healing has neither that5minute damage delay nor a node-table guard. Thus neither “all creature regen is disabled” nor “current combat universally suppresses regen” is established. Do not invent a new balance rule from these discrepancies.

**No players / encounter end:** resolver ends when no living engaged creature or qualifying active effect remains, not merely when fighters are absent. Existing pending actions/effects/tanks are processed under source rules; an engaged living creature can keep an empty encounter active. End/reactivation does not universally reset creature HP. Due-node discovery has no present-fighter predicate, as already established by G3. No unconditional orphan/despawn sweep on last-player departure was established in the inspected creature path; existing cleanup helpers and installed behavior are separate evidence questions, not proof of absence globally.

**Sleep / wake:** G3's presence/live-claim idle decision is independent of encounter.status. Shutdown stops/removes source-named scheduling and can leave active encounters stored. While asleep without eligible dispatcher/tick invocation, no source mandate runs those loops. Ordinary respawn uses wall-clock died_at+respawn_seconds when its helper next runs; roster's respawn_pending count does not itself perform respawn. Wake rearms legacy creature scheduling and calls full-heal helper; there is no established elapsed-sleep creature-regen settlement algorithm here. Legacy world_is_awake activity gating differs from canonical singleton gating, so timing/runtime depends on installed composition. Historical F10 sleep success is bounded owner evidence, not fresh verification.
