Record contains only account identifier and immutable character/material/amount/request UUID payload; no JWT, session, credentials, email or service data. Panels obtain account from existing useAuth, never derive it solely from selected character ownership. Unauthenticated/wrong-character submission refuses. Validated schema/record scope/quantity/UUID prevent stale or malformed records being adopted; corrupt/unreadable storage fails closed rather than replacing an unknown request.

Persist before request dispatch, recover without dispatch, explicit Retry pending sale control remains visible at zero stock. Same account/character across both panels reads the stored request again at submission; changed slider does not replace it. Shared same-tab in-flight guard prevents competing mounted-panel requests, and local notification synchronizes pending display. Auth/character switching selects a separate key, leaving old request available when original scope returns. Response from an earlier scope clears only that key, not a new account's pending request.

Authoritative success must now echo matching request_id from the updated Edge as well as matching amount/key and valid balance; explicit matching not_committed remains the only refusal-clear contract. Generic HTTP/network errors retain storage. Clear only after validated outcome; storage-removal failure preserves record for safe replay. Database SQL unchanged; Edge change only echoes UUID on success. New bundle must be deployed/published together under database-first order. Old success responses lacking UUID stay ambiguous; no fallback creates a new UUID.

Session storage is sufficient for same-tab panel close/reopen/remount and ordinary page reload without a new DB table/service. Limits: tab/session closure or cleared storage loses recovery; independent tabs hold independent requests and can make separate legitimate paid sales. A duplicated tab may inherit copied session storage and safely replay the same UUID, but there is no cross-tab coordination guarantee. Unresolved results remain blocked until explicit retry returns definitive outcome; no cancel/new-award escape.
