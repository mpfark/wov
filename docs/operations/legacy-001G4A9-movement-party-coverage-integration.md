## Coverage, lock order and HP protocol

1. Discover actor and party (including all accepted/pending/off-node membership), character nodes/deleted state, origin/destination, all relevant current-generation creature/projection rows, fighter encounters, active party arrival groups and pending/queued departure references. Deterministic JSON captures identity/coverage, not HP values. Discovery is candidate code; source predecessor still validates authority and derives actual movers.
2. Acquire deduplicated sorted node advisories → `party-lifecycle` → compare discovery → sorted existing encounter row locks → compare again. Changed coverage raises40001 **before dependent character row locks**. No internal loop or late node acquisition. A test holds a node gate and verifies another session can lock the mover characters NOWAIT while the movement caller waits; separate inspection confirms origin/destination/off-node gates held.
3. Foreign-node retained projection is covered in discovery but then explicitly refused; it is not healed, reassigned or automatically repaired. Generation changes also invalidate discovery. Full arbitrary external/raw-table changes are outside these cooperative guarantees.
4. Under that coverage, lock/settle only origin/destination creatures for movement, or destination creatures for standalone attachment. Off-node member coverage does not authorize changing their creature HP/claims. Each creature set is sorted irrespective of incoming discovery order. Call the existing candidate accounting authority; no second formula/writer is introduced. Fence superseded leases inside the success/refusal savepoint, settle old eligible time, synchronize retained projections and preserve wholeHP before source attachment.
5. Call the full supported source chain. Source party predecessor re-enters held lifecycle/node/encounter locks, freezes the mover set and obtains UUID character locks before creating requests. Source finalizers preserve creature-targeted DoTs; arrival engages/creates/reactivates the destination. Reconcile post-state only after accepted new work; successful committed replay does not perform fresh settlement. JSON refusal rolls back accounting, claims and source mutations in the enclosing savepoint; SQL exceptions roll back the transaction.
6. Missing destination encounter remains absent until the **actual source arrival body** creates it. Its node gate is already held; the new row belongs to that same transaction, not an unheld pre-existing encounter acquired after character locks. A concurrent arrival that discovered the absent row refuses changed coverage after waiting, then succeeds on explicit fresh retry. This is bounded proof for cooperating node-gated callers, not proof against privileged inserts that ignore gates.
7. DoT/pending work, not departure alone, governs eligibility. Last-blocker removal via the source commit fragment starts the60-second delay. Movement to a creature at t126 preserves45 wholeHP and discards the earned half-HP credit on attachment; retained runtime ID/generation and HP remain coherent. Ordinary due respawn still uses the unchanged source body/generation trigger, including zero-rate creatures.

The source request-specific advisory is acquired after the candidate's early encounter coverage; supported wrappers already gate nodes before requesting it. Private/raw predecessors that bypass the node contract are **not** declared lock-compatible. F6's existing conservative coverage refusal remains intact, including in the reverse movement-first/membership race. No whole-system deadlock-freedom or actual caller-isolation assertion is made.
