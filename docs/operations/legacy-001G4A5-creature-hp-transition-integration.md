## Conclusion and minimal integration boundary

One private, transaction-local **node/generation settlement and eligibility reconciliation authority** should own passive healing/accounting and synchronized projections. Supported entry/intent/stance, claim and commit, immediate departure/arrival, ordinary respawn and protected Admin writes must compose with it. The pure resolver remains pure and does not become a passive-regeneration writer. A scheduled helper alone, an HP-only trigger, or a post-commit wrapper alone cannot observe the complete eligibility timeline or invalidate already returned claims.

Preserve existing actor ownership, lifecycle, mode, request and Admin authorization at the outer boundaries. The new private helper must have explicit narrow internal/server EXECUTE intent, no browser-callable raw HP or elapsed-time authority, and a fixed security/search-path contract. Keep Arena isolation; routine shared-world maintenance must not silently heal isolated test fixtures. Exact installed grants/callers remain a later scoped gate, not grounds to widen access now.

Required composition is smaller than a Combat2 rewrite, but larger than replacing the two healing functions. In particular, an intent can start/end between maintenance calls, movement can remove the last aura source, and an ended projection survives seeding. Existing generic Admin writes must be guarded before activation. G4-R1 remains OPEN; candidate authoring requires separate authorization and the decisions in section6.

## 2. Transition-hook matrix

“Reconcile” means compare locked pre/post blocker state for the exact generation; settle only previously proved eligible time, then record a release/start/reset at one server cutoff. A repeated observation of the same state must not reset the delay. All rows below are proposed hooks, not newly implemented calls.

Settle old eligible HP; seed/synchronize; post-entry reconcile relevant creature eligibility. ## 3. Proposed ownership and transaction protocol

| State | Intended writer / invariant |
|---|---|
| creatures.hp / is_alive / generation | Durable HP authority. Combat outcomes use existing validated commit mirror; passive settlement is the only ordinary-healing writer. Death/respawn remain existing owners, composed with accounting. |
| node_creature.hp | Combat2 projection of the same creature/generation, never an independent healing balance. Runtime damage proposal and durable mirror commit atomically; passive changes synchronize matching retained projection. Global uniqueness permits at most one row per creature/generation in the inspected schema. |
| eligible_since / accounted_through / fractional credit / rate | Private generation-scoped accounting. No browser-written HP/cursor/remainder. Exact-decimal policy below; one shared computation, no independent wake balance. |
| encounter claim/token/version | Existing encounter authority; not the proof's artificial per-creature version. HP or snapshot-relevant blocker changes invalidate prior snapshots under encounter lock. Cursor-only same-HP changes do not automatically need encounter invalidation if they cannot change a claim's gameplay inputs. |
| reward/death claims, encounter tick | Existing generation/death/participation protocol unchanged. Regeneration does not advance a combat tick, revive a generation, grant XP/gold/items or alter reward claim keys. |

### A. Lock discovery and ordering

1. Discover affected node IDs and encounter IDs, including origin/destination for relocation and retained same-generation projection's encounter. Acquire sorted `combat_enter_node:` advisory gates first. If party lifecycle locking is already required, preserve its position after all node gates and before dependent row work.
2. Acquire relevant encounter rows deterministically before new dependent creature/projection/character/member locking. Revalidate node assignment, generation and projection coverage; drift means retry/refusal, never acquire a new node after row locks. No-projection cases still require the node gate to serialize seed/entry creation.
3. Follow existing inner commit ordering for dependent writes (not a generic creatures-first scan). Newly exposed rows must be included before calling a predecessor; do not add an encounter lock from its post-hook after character/creature locks. Node-scoped gates serialize supported same-node entry/claim/maintenance paths, including missing encounter cases.
4. Source caveat: arrival currently obtains the character row before its encounter (A180/202), while immediate movement predecessors prelock encounter coverage and outer commit prelocks node coverage. The proposed common helpers must **not** infer that every caller already follows a perfect universal row hierarchy. Move/pre-acquire needed coverage in the top-level caller, not a deep trigger. Existing privileged/legacy lock uncertainties remain; source inspection is not a deadlock proof.
5. No blocking node lock in a creature BEFORE/AFTER UPDATE trigger: the statement may already hold that row, reversing maintenance's node→encounter→dependent order. A row trigger can reject unauthorized protected-field writes without taking higher-level locks, but a caller-set GUC alone is not a security boundary. Exact guarded-role/private-authority implementation and privileges need separate design/metadata review.

### B. Passive settlement, claim and post-transition reconciliation

Under coverage locks, verify exact durable/projection generation and HP consistency and evaluate pre-state blockers. Capture one monotonic server cutoff after locks. Settle only the proved eligible interval up to it using the G4A4 exact arithmetic and existing accounting cursor. No speculative historical release time. Synchronize HP/accounting/projection in the same transaction; if an expired/stale snapshot could still propose the old HP, bump encounter state_version and clear stale claim metadata. Do not steal a valid live claim merely to heal; defer passive maintenance instead.

Pre-claim settlement occurs before a new lease is issued. The returned snapshot must contain the resulting HP and expected version. Claim-before-maintenance with a live lease defers the latter; maintenance-before-claim makes the new snapshot authoritative. After lease expiry, settlement/version invalidation rejects the old worker result. Row locks alone cannot reject a snapshot returned by a completed earlier claim RPC.

An authoritative entry/intent/departure can already invalidate a live claim under its existing semantics; compose accounting into that transition rather than applying the passive deferral rule blindly. Ordinary combat potential must be closed at admission/entry, not only when damage eventually commits. A quiet claim is not automatically combat: do not repeatedly reset its delay simply because an empty encounter is still active.

After a new commit or immediate mutation, derive blockers from committed-in-transaction post-state; do not trust only the proposed HP list because an unchanged creature may not be proposed. Start the delay at the proved release cutoff, never retroactively at a wall-clock expiry while effects were unresolved. Where existing entry/commit already increments version and clears claim, compose the hook before returning without a redundant second increment. Cursor-only writes may use their own locked accounting check; no new per-creature claim version is automatically required.

**Atomic failure rule:** hook writes must be inside the same success transaction/subtransaction as the supported operation. Returning JSON `ok=false` does not itself roll back writes. A future wrapper needs an explicit refusal savepoint/exception strategy if it performs accounting before calling a predecessor that returns refusal. Preserve original result contract and already-committed/replay fast path; do not heal as an accidental side effect of a rejected request. Database rollback/failure injection must test this, not just the pure immutable model.

### C. Ended projection, node reassignment and Admin boundaries

Retained ended projections remain subject to synchronization. Seed's DO NOTHING cannot implement it; a validated current-generation row should match durable HP before claim/reactivation. A pre-existing unexplained mismatch is a disposition gate, not authorization to choose either copy or heal it. Do not remove historical rows or rewrite prior migrations.

Reassignment to a new node is more than changing creatures.node_id: global UNIQUE(creature_id,spawn_seq) prevents a second projection while the same-generation row remains attached elsewhere. Active attachment must be refused as approved. For quiet ended attachments, compare (a) explicit locked detach/rebind preserving runtime identity/history and validating no unresolved work, versus (b) deferring reassignment while a retained current-generation row exists until a targeted transfer contract is approved. **Recommend conservative deferral initially**, not an unreviewed delete/reseed or new generation. This stricter inactive-case policy needs owner approval; it does not change the approved active-case rule.

Admin requires a narrow authoritative configuration/maxHP/reassignment boundary and minimal caller adaptation in CreatureManager and NodeEditorPanel; populate/new creation needs accounting initialization. Avoid changing rewards/regions/items or rebuilding Admin. A row-level rejection fence alone would make current saves fail, so compatibility/caller adjustment is part of the future coherent cutover, even if the new regeneration UI is deferred. Known effective table privileges and external raw writers remain unverified. Do not activate while the generic save can independently refill HP.

### D. World heartbeat / legacy delegation

Use one existing authoritative heartbeat opportunity for bounded passive maintenance, plus necessary pre-entry/pre-claim settlement. If added to its SQL transaction, place the node-gated phase before character OOC resource settlement acquires character rows; adding node locks afterwards risks an inverted dependency. Retain heartbeat identity, mode/world gates and scheduling behavior. This placement is proposed; exact installed outer function composition must be reconciled before a candidate is declared ready.

Wake must stop independent full healing; do not add bulk node/encounter work after its existing DDL locks. Legacy regen must stop independent HP writes without preventing the following ordinary respawn call. Options are a nonmutating compatibility return for the void/count interfaces with documented retirement, or delegation only from a caller with the required early lock coverage. Prefer nonmutating old healing shells and canonical bounded settlement, preserving the existing respawn schedule. No new scheduler or G3 race repair. Sleep retains proved eligibility; unresolved effects/actions keep it closed, not resolved by elapsed wall time alone.

## 4. Accounting choices requiring explicit disposition

Approved default5, decimal0–100, zero-disable, initial5/no historical credit, 60-second delay, ordinary respawn and active-attachment edit refusal are **not reopened**.

| Decision | Alternatives | Recommendation, not silent approval |
|---|---|---|
| Fraction on combat interruption | Discard accrued fraction, or preserve already-earned fraction while resetting delay. | Preserve exact earned fractional HP; combat elapsed earns nothing; restart full60seconds after last blocker. Clear only on fullHP/death/new generation. Confirm with owner before production. |
| Rate change / disable | Clear fraction/restart delay, or settle old rate through cutoff and preserve exact fraction/quiet history; disabled interval earns0. | Preserve earned fraction and continuous eligibility; future time alone uses new rate. Enabling after a quiet disabled interval creates no historical healing. Confirm this across0 and nonzero changes. |
| Wounded maximum-HP edit | Refill, preserve damage ratio, or preserve absolute HP with downward cap. | Settle under old max/rate to cutoff; preserve absolute HP on increase, clamp on decrease, no refill, discard surplus at full. Restrict/reject such edits under active attachment initially. Choice affects gameplay and requires approval; do not reuse generic generated full-HP payload. |
| Decimal/time representation | Arbitrary decimal + rational numerator/denominator (G4A4), or bounded exact decimal scale + one fixed-denominator remainder. | Propose four decimal percentage places (0.0001%) and exact server microseconds, with no float conversion or silent rounding. Reject finer input explicitly only after owner agrees the supported precision. Rate0–100 unchanged. Scaled integer rate0–1,000,000; remainder denominator=100×10,000×60,000,000=60,000,000,000,000; whole/remainder arithmetic in checked wide/exact types. G4A4 arbitrary precision remains reference, not proof of this proposed native representation. |
| Persistence bounds | Unlimited numeric work versus bounded input/storage/time. | Proposed stored fixed remainder fits signed64-bit, but maxHP×rate×elapsed can exceed it; use exact wide arithmetic or bound calculation to time-until-full before multiplication. MaxHP column/domain and timestamp limits need source/installed reconciliation; no invented balance cap. Preserve exact cutoff quantization, not per-call time truncation. |
| Existing initialization / reassignment | Retroactive credit/automatic mismatch repair versus explicit cutover with refused unknown states. | As already approved, rate5 and no prior credit. Initialize quiet eligible-since no earlier than T0, blocked/unknown closed; check mismatch and old projection first. Defer unresolved rows for individually approved disposition. Additional quiet-ended reassignment policy above needs approval. |

With selected fixed precision, proposed minimal additions are rate, nullable eligible-since, accounted-through, fixed-denominator fractional remainder (four conceptual values) on durable creatures, scoped by existing spawn_seq. No new HP table/service/receipt framework is justified. Selecting arbitrary precision instead retains G4A4's five-value rational model. No DDL is authored, and protected-column/caller validation is part of implementation, not supplied by this report.
