## Local ownership and locking protocol

| Stage | Locks/fence | Accounting / synchronization |
|---|---|---|
| Discover movement | Read immutable fixture request origin/destination or current arrival node | No HP writes; full party membership discovery is upstream and omitted. |
| Cover | All distinct nodes sorted by UUID → existing encounters sorted by UUID | Revalidate request/node coverage. A current-generation projection attached to a different node refuses with40001; no late extra node acquisition. New/missing encounter creation and off-node mover discovery remain further work. |
| Before destination arrival | Under covered gates/encounters, candidate locks current-generation projection/creature; fence superseded destination lease | Settle old quiet eligibility before source character relocation/engagement/seed. Ordinary source entry/arrival still performs its final version fence. |
| Solo/party finalize | Preheld encounter coverage → source character/fighter/request locks; party parent/member locks are within that early coverage | Full source removes player participation; source arrival trigger seeds/engages destination from settled durable HP. Reconcile origin/destination after finalization. Failure raises/rolls back accounting and relocation together. |
| Last blocker removed | Same transaction; inspect remaining source/target effects, pending action/intent/event and presence | Departure alone grants no eligibility. Preserved creature DoT blocks; no residual work starts the60-second delay at departure cutoff. No retroactive eligibility credit. |
| Guarded metadata | Candidate node → encounter → dependent rows | Rate/max refuse active attachment, including live claim. Rate settles old rate, applies wholeHP, discards fraction, new cursor/rate; quiet eligibility is preserved. Rate change explicitly fences retained encounter even without wholeHP change. Max preserves missingHP with living floor1 and synchronized projection/version fencing. |
| Reassignment | Sorted old/new gates → both encounters → projection/creature; discovery revalidation | Current candidate only supports known ended destination encounter. Active/blockers/outstanding claims refuse. Quiet ended transfer retains generation/runtime identity, synchronizes HP and fences both encounters. |
| Raw Admin/delete | No late-lock row-trigger retrofit | Protected generic payload refuses atomically; only isolated name edit supported. Retained projection makes delete refuse rather than deleting history. Raw table UPDATE remains technically possible for fixture owner and production Admin; this is not implemented database containment. |

Current source arrival acquires its character lock before the encounter. Calling a newly locking HP helper only inside its late trigger would invert the required ordering. The local outer adapter prelocks coverage first. Similarly, acquiring node gates inside an Admin row trigger after its row is already locked is unsafe; a production design needs a guarded server boundary plus raw-write refusal/authority design, not a caller-settable bypass GUC. No new browser privileged API or grant is added here.

The fixture's party finalizer takes parent/member locks after early encounter coverage, but does **not** run the production party-lifecycle advisory predecessor. The accepted node → party lifecycle → encounter → character hierarchy remains binding. Full party follow across arbitrary off-node accepted members and concurrent membership mutation is unproven. Combat1 cleanup can still acquire its legacy encounter gate late; its accepted unresolved lock-order risk is retained. No global deadlock-freedom conclusion follows from these eight races.
