## Equipment — confirmed source root cause

Chain: [CharacterPanel Equip buttons / equipped-slot Unequip](../../src/features/character/components/CharacterPanel.tsx) → [GamePage charPanelProps callbacks](../../src/pages/GamePage.tsx) → [useInventory](../../src/features/inventory/hooks/useInventory.ts) → authenticated PostgREST RPC public.character_inventory_action(uuid,text,uuid,text,uuid). **No Edge Function is in this equipment chain.**

Before this correction GamePage wrapped both callbacks with useControlledAction(legacyExecution.allowed,…). [Legacy rollout selector](../../src/features/combat2/browser-presentation.ts) returns rolloutEnabled OR ownershipReserved, and GamePage constructs its legacy fence from its negation. With Combat2 enabled, a normal OOC Equip/Unequip click therefore stops **before sending a request**, only setting the Combat2 diagnostic (generic movement-disabled text), not the visible inventory error log. This source-proven path explains the reported no-op and applies equally to the newly crafted item and older gear. The identical wrappers exist at 8441598f^, before the crafting restoration: no evidence that crafting caused this regression.

Drop/pin use the same underlying inventory authority but bypass that wrapper; pickup uses its existing loot path. Their reported success is consistent with this separation. These working operations and crafting are unchanged. There is no evidence that the reported blocked clicks committed silently; after removing this blocker a separate installed RPC refusal is possible and must be reported rather than guessed.

The hook also discarded RPC error and ok:false responses; only ok:true triggered refresh. This secondary source-confirmed feedback defect hid permission/state/slot/stance refusals. Resource synchronization runs in a later RPC and ignored its returned error. Successful equipment mutation with failed sync is a partial outcome, not a failed/rolled-back equip.

Combat2 rollout itself and world maintenance/access policy are not an inventory ban. Legacy active-combat blocking stays in place. CharacterPanel receives this equipment lock separately; unrelated combat UI is unchanged.
- The hook reports transport errors, malformed results, local durability/two-hand blocks and named server refusals to the existing visible event log. It single-flights gear requests; success awaits inventory reload and existing resource synchronization/character refresh. On uncertain transport it reloads inventory, without assuming the request committed or automatically resubmitting. A sync error explicitly says equipment changed but synchronization failed.
- Ring-slot selection and two-hand checks are preserved. This is not a redesign of inventory idempotency or a fix for every equipment callback/transactionality problem.
