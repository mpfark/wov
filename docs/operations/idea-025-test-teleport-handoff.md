## Implemented boundary

- Existing gameplay login, existing `admin-users` Edge, existing Admin `NodePicker`; no extra Admin role/login. Two exact test-only actions authenticate with `getUser()`, derive actor server-side and invoke service-only RPCs. All other actions still use `verifyAdmin`; retired `teleport` remains410.
- `gameplay_test_destination` is a private **empty** registry of exact account/character/destination UUID triples. There are no name-based rules, seeded identities, browser grants or new roles. SQL checks current ownership/lifecycle and approval, first cheaply and again under locks. Approval is held through commit. Arena nodes are excluded. Only approved destinations are returned to that account/character.
- Strict initial solo scope: any party membership, including invitations, or leader/tank association refuses. Dead/deleted characters, movement locks, queued solo departures, queued/waiting party movers, present fighters, active encounters, retained claims (even expired), effects/actions/events and relevant legacy state refuse. Conservatively refuses an active source/destination encounter even if it belongs to someone else. No forced escape, party detach, claim cancellation or reward cleanup.
- Request UUID binds actor, character and destination. The origin is discovered server-side on first execution, never client-selected. Exact replay returns the original receipt **without moving again**, even if the character has since moved; different payload/actor refuses. Replay precedes mutable authorization/availability checks after trusted service-context validation. Historical receipts cannot authorize another relocation.
- Session storage persists immutable payload **before dispatch**, scoped to authenticated account and character. Reload/remount offers an explicit retry; no automatic teleport. Competing same-tab submissions are blocked. Only matching committed or explicit transactional `not_committed` responses clear recovery. HTTP status, timeout and ambiguous responses retain it. Storage failure blocks dispatch. No credentials are stored.
- No CP/MP/HP debit, XP award or change to normal travel rules. This is a test-only relocation exception; normal player teleport, ordinary walking/departure and progression controls remain untouched. The client refetches canonical character state after success; it never writes a local position as authority.

## Canonical movement and lock composition

`gameplay_test_teleport_internal` → installed0024 `creature_hp_cover([origin,destination],[character])` → account eligible creature HP → authorized character relocation → existing `combat2_authoritative_arrival` trigger → 0024-wrapped `combat2_arrive_after_relocation` → existing spawn seeding/tank/entry-event handling → account HP → receipt. The position UPDATE is one step inside this transaction, not a replacement for movement/arrival authority. Existing participation/lifecycle triggers remain enabled.

Order: unique request advisory key → discover closure → sorted `combat_enter_node` advisory keys → `party-lifecycle` → sorted encounter/projection/creature rows → retained Combat1 encounter keys (nonblocking try-lock/refuse) → character `FOR NO KEY UPDATE` → approval SHARE/receipt. Coverage is revalidated by0024 before/after dependent rows; origin is checked after the character lock. No late node acquisition is permitted. The arrival wrapper inherits the early coverage; any coverage expansion or source change fails closed. Newly created destination encounters are protected by the already-held destination gate. The operation explicitly refuses transaction isolation other than READ COMMITTED rather than silently changing it.

Supported entry/claim/movement/Admin writers share those gates; see [0024](../../drizzle/migrations/0024_g4a21_shared_creature_hp.sql) `creature_hp_discover/cover/account` and the [arrival source](../../supabase/migrations/20260928100000_combat2_authoritative_arrival_hostile_initiation.sql). The [retained cleanup source](../../supabase/migrations/20260827094512_37a985a4-cb14-4ce8-9a04-43f75cd26184.sql) can swallow cleanup failures. This candidate pre-refuses legacy participation/pending state and does not rely on that swallow for correctness. It does not repair or prove global deadlock freedom against arbitrary privileged/Combat1 writers; the owner-accepted Combat1 risk remains.
