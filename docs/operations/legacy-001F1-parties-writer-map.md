## Leadership and source authority observations

Supported leader_id assigned on create; no transfer command exposed by PARTY_OPERATIONS/useParty/PartyPanel. Disband/recreate is not atomic leadership transfer and should not be presented as one. Generic service/table UPDATE capability can change leader/membership outside the coordinator; do not infer an active legitimate caller, browser exploit or gameplay policy from that capability. restrict_party_leader_updates name is not a party leadership fence: earlier C evidence binds it to characters, not proof all parties updates are guarded.

Party mutation tables/UUID requests are within one SQL transaction. Source global lifecycle lock freezes mover membership against **ordinary** supported membership mutations. It does not establish protection against raw service DML or every admin/cascade action. party_combat_mutation_blocked reads active present fighter/pending departure/live claim predicates without taking node/encounter locks itself; combat entry/claim paths may change state around that read. No demonstrated corrupt movement result; this is the relevant unproven membership/entry serialization boundary, not automatic proof the global lock is broken.
