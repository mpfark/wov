## Evidence boundary and reused work

This audit follows application routes/barrel exports, callback guards, static/dynamic imports, literal and adapter-generated RPC names, SQL calls/renames/triggers, Edge handlers, historical scheduled consumers, mirror generators and representative admin consumers. Text-search absence is only supporting evidence, not proof of an absent installed or external caller. No Cloud catalogue, schedule, browser, credential or gameplay inspection occurred; no executable tests were run for this documentation task.

Reuse, with these limits:

- [L1 privilege checkpoint](legacy-cleanup-l1-checkpoint.md): historical revocations and retained bodies, not today's effective grants. Its once-open character UPDATE and Force Shield gaps must not be treated as fresh findings: later hardening/stance releases exist.

- [Movement audit](combat2-movement-departure-audit.md) and [targeting audit](combat2-targeting-initiation-audit.md): reuse authoritative routing, identity fences and release decisions; refresh their old encounter-only stance assumptions against the installed-source stance wrappers.
- [Persistent stance design](combat2-ability-availability-and-persistent-stances.md): its pre-implementation baseline is historical. Current `useGameLoop` has no regeneration timer and no browser calls `apply_force_shield_regen`; character-owned stances and ACL correction are Lovable-reported installed. Preserve the already completed one-time reset; never replay it.
- Project state records stance/helper ACL installation, earlier operator movement/recovery and bounded cadence evidence. These are not fresh catalogue verification. Mik now reports the OOC CP presentation correction works; this does not prove death/respawn, Force Shield, Arena or multiplayer branches, nor an observed server regeneration trajectory.

## Current authority and reachability

[feature-flags.ts](../../src/shared/config/feature-flags.ts) sets `COMBAT2_CLIENT_ENABLED = true`. [GamePage](../../src/pages/GamePage.tsx) mounts legacy hooks but supplies `enabled/combatEnabled: !combat2BlocksLegacy`. [useCombat2TestOwnership](../../src/features/combat2/useCombat2TestOwnership.ts) reserves ordinary located characters before access/preflight completes, including refused access; Arena location also reserves legacy authority. A refusal never enables Combat1. A node-less character or a future source switch to false is a different reachability condition, not proof that legacy APIs no longer exist.

[ExecutionFence](../../src/features/combat2/execution-fence.ts) invalidates captured callbacks across suspension and awaits. `GamePage.updateCharacter`, `guardedCharacterLocal` and `guardedClearFields` reject combat/resource/location mutations while reserved. The raw callbacks passed to the legacy death hook are protected by that hook's execution fence, not by those wrappers. Preserve both levels until that caller is retired.

Current replacements are `combat_enter(uuid,uuid)`, hostile action/intent RPCs, `node_tick_claim(uuid,integer)` → strict decode → catalogues → `resolveNodeTick` → `node_tick_commit(uuid,uuid,integer,integer,bigint,uuid[],jsonb)`, four-second `settle_out_of_combat_resources(timestamptz)`, immediate `combat2_depart(uuid,uuid,uuid)` / `combat2_party_depart(uuid,uuid,uuid)`, `combat2_respawn(uuid,uuid)`, and character stance projection/change RPCs. Their locks, request ledgers, version fences and delivery cursors remain authoritative. Heartbeat is correlation metadata, not browser gameplay order.

Classification legend: **A** active authoritative dependency — retain; **S** shared utility/content dependency — retain; **O** obsolete reachable path — isolate/replace before removal; **U** source-proven unused candidate — bounded removal possible; **H** historical migration/test evidence — preserve; **C** uncertain installed dependency — read-only Cloud verification required. Confidence refers to source reachability, not Cloud state.

## Active SQL composition: retain, not a blacklist

Exact overloads and bodies must be checked from installed `pg_proc`, not inferred by sorting repository filenames/ledger duplicates. The following positive source dependencies already rule out deletion:

- Stance migration wraps `combat_intent(uuid,uuid,text,text,text,uuid,uuid,uuid)` → `combat_intent_without_character_stances` with the same signature; older global-lock-order and spendable-CP predecessors are composed below it. Claim `(uuid,integer)` → `node_tick_claim_without_character_stances` → boss-timing/canary predecessors. Commit `(uuid,uuid,integer,integer,bigint,uuid[],jsonb)` → `node_tick_commit_without_character_stances` → arrival/bounded-failure predecessors. The drift correction patches the inner `node_tick_commit_without_bounded_failure`, not a disposable alternate resolver.
- Immediate departure `(uuid,uuid,uuid)` and party departure `(uuid,uuid,uuid)` call their `*_without_immediate_transition` predecessors and immediate finalizers. Arrival wrappers preserve `*_without_canary_gate`; newest entry/tank priority and follower-first/leader-last must survive. The removed `combat2_party_departure_member_finalized` trigger is historical evidence, not a trigger to restore.
- Scheduler `combat2_dispatch_scheduler_fire()` currently calls `settle_out_of_combat_resources(timestamptz)` and `combat2_dispatch_scheduler_fire_without_resource_settlement()`, separately protected failure branches. Settlement delegates to `settle_out_of_combat_resources_without_character_stances(timestamptz)` then regenerates wards. `combat2_dispatch_scheduler_fire_without_heartbeat_identity()` is not the direct dispatch callee of the current outer wrapper; retain as an uncertain installed/rollback predecessor until a full catalogue graph is reviewed.
- Canonical `combat2_test_stop(uuid,uuid)` / `combat2_test_reset(uuid,uuid,boolean)` call `*_without_character_stances` then `combat2_restore_arena_stances(uuid)`. Stop also preserves the earlier event-finalization chain and `combat2_test_stop_without_event_finalization`. Browser denial on inner helpers does **not** mean the public admin wrapper should be removed or revoked.
- Retain character stance tables/request ledger, Arena snapshot header/rows, claim version projection, commit/death cleanup and class/equipment invalidation triggers. `combat2_refuse_invalid_stance_class_change()` / `combat2_refuse_invalid_stance_equipment_change()` enforce current approved rules. Arena reset/stop restore captured pre-run stance state; ordinary death clears it. They are intentionally different lifecycle boundaries.

## Recommended first removal batch (separate authorization)

**ENG-LEGACY-002 batch A: remove only the unreachable resolver tails from the two retired Edge entry files.** This is source-only cleanup with subsequent deployment, not SQL retirement or deletion of the endpoints.

1. Leave `OPTIONS` and all other methods' `410` / `legacy_retired` response, CORS, build stamp and safe boot behavior unchanged. Remove code after the complete method-return partition and only imports/constants/helpers used exclusively by that removed tail. Do not remove `_shared/combat/**`, generators, catalogue data or tests wholesale.
2. Prove that current callers, dynamic application imports and every Edge consumer still resolve. Check module import-time side effects explicitly before removing an import; retain one if it has a required side effect. No other function/module export is in scope.
3. Extend `legacy-cutover-edge.test.ts` / focused handler coverage for OPTIONS, POST and other methods, exactly the same refusal shape, and no client/DB construction or resolver invocation. Run relevant roster-authority/client legacy-execution guards, C3 mirror parity, Edge packaging/containment, TypeScript and frontend build only if its graph changes. These are future implementation checks, not checks run in this audit.
4. Schema/ACL/frontend: none intended. Official types, function grants, cadence, CP/reservations, rewards, movement and admin authoring remain unchanged. Deployment dependency list for this batch is exactly `combat-tick` and `combat-catchup`; do not redeploy Combat2 functions or publish frontend merely for this cleanup.
5. Order: verify tests and reviewed checkpoint → normal push → separately authorized deployment of the two refusal shells → installed/deployed revision inspection and bounded passive error monitoring. Do not wake the world or invoke gameplay to prove code deletion.
6. Recovery: normal Git revert/redeploy the previous **retired** shells; never restore pre-retirement gameplay handlers as a cleanup rollback. Historical SQL/data are untouched.

This batch does not require proving that nobody calls the endpoints, because their externally visible refusal contract remains. **Endpoint removal** would require external/old-client/scheduled caller evidence. A later frontend batch should isolate entry `clear_stances` and OOC legacy ward/broadcast presentation, with explicit reservation/ward/log/party transition tests, before considering a SQL change.

No `DROP CASCADE`, historical migration rewrite, manual official-type deletion or blanket C3/Combat1 removal is recommended.

## Rules preserved

One world heartbeat; two-second encounter opportunities; four-second OOC settlement; immediate authoritative movement; character-persistent stances with current percentage reservations; server-owned resources and deterministic commit fencing. Presence/online timers, recovery polling, UI expiry clocks and diagnostic batching are not competing gameplay clocks. Full ability expansion, authoritative food design, broader gear/crafting and admin redesign remain their existing later roadmap work.
